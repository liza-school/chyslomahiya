## Рушій переливань (`course/js/jugs.js`, `course/css/jugs.css`)

* `JUGS.create(cfg)` — симулятор: кнопки набрати/вилити/перелити; після переливання з новим числом відро під «кришкою»
  і питання «скільки тепер» (лити далі не можна); таблиця кроків як у підручнику; повтор стану червоніє; ліміт; «Крок назад»;
  після розвʼязку — найкоротший шлях (BFS). Поруч живий **більярд** (стан — точка, крок — відрізок, номери кроків,
  під кришкою лише напрямок). На ширині ≥ 700 px більярд праворуч від відер.
* `cfg`: `vessels`, `start`, `source` (`lake|tap|river`, без нього — замкнена система з великою посудиною першою),
  мета `target`(+`targetIn`) | `exact` | `collect`, `limit`, `liquid` (`petrol|milk|butterbeer|pumpkin`), `where`, `intro`, `forbidden`.
* `JUGS.table(cfg, ["F0","P01","E1",…])`, `JUGS.billiard(cfg, ходи)` — для розвʼязань; літри рахує рушій, хибний хід → помилка в консолі → `check.js` падає.
* `JUGS.stateMap(cfg, глибина)` — карта ходів рядами (№ 14). `JUGS.walk(cfg)` — покроковий граф станів (блок `jugwalk`).
  `JUGS.explore(cfg)` — дитина сама перевіряє всі ходи й будує карту; `coach` у `JUGS.create` навчає правилу кола
  з підсвічуванням (`show`) або без нього (`practice`). Під усіма симуляторами із метою є згорнута запасна карта.
* `JUGS.trainer` — тренажер 1–20 л, НСД, «рівно найкоротший» ліміт. `JUGS.shortest`, `circleRow`, `gcd`.
* Типи блоків у `engine.js`: `jugs`, `jugtrainer`, `jugwalk`, `jugmap`; у задачі — поля `jugs` і `map`. Описано в `COURSE.md`.

## Перевірені перебором факти (не переписувати без нового перебору)

* Дві посудини з озером, усі пари до 20 л: досяжне ⇔ ділиться на НСД і ≤ більшого; точне коло (давача доливають лише порожнім,
  приймач виливають лише повним) доходить без повторів; коротше з двох кіл = найкоротший шлях; недосяжне — коло замикається.
* Рядок кола: ближче до початку — мале у велике, до кінця — велике в мале, рівно посередині — мале (ніколи не довше).
* Граф рядами для двох відер — ширина 1, 2, 3, 2, 2, … = дві доріжки = два кола.
* Три посудини без озера: коло завжди доходить, але ≈5 % випадків не найкоротше (8/3/1 → 4: 2 кроки проти 7) — сказано в тексті.

## Аналітика сайту — відкладено

Валерій хоче бачити, скільки людей заходить на навчальний сайт. Вбудований `Insights → Traffic` у GitHub показує
трафік репозиторію, а не відвідування GitHub Pages. Минулі відвідування сайту відновити неможливо; конкретні імена
або IP відвідувачів власнику сайту не показуються.

Погоджений практичний варіант — безкоштовний **Cloudflare Web Analytics**: без cookies, без зміни DNS і без перенесення
з GitHub Pages. Він показуватиме майбутні перегляди, країни, пристрої, джерела переходів і популярні сторінки.
Потрібно: Валерій створює безкоштовний акаунт Cloudflare, додає hostname `liza-school.github.io` і передає виданий
JS-фрагмент. Після цього вставити beacon лише для `https:`/онлайн-версії, щоб подвійний клік по локальному
`course/index.html` і весь курс без інтернету працювали як раніше. Окремо перевірити облік hash-маршрутів уроків
(`#/l/l01`, `#/l/l02`, `#/l/l03`), бо сайт — односторінковий.
